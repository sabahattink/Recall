# Web deployment (planned, not yet performed)

This document describes the intended future deployment of `apps/web` to Vercel. **No deployment,
DNS change, or Vercel project has been created as part of this document.** It exists so the
deployment is a mechanical, well-defined step whenever a maintainer chooses to perform it.

## Vercel project configuration

| Setting          | Value                                                                                                      |
| ---------------- | ---------------------------------------------------------------------------------------------------------- |
| Repository       | `sabahattink/Recall`                                                                                       |
| Root directory   | `apps/web`                                                                                                 |
| Framework preset | Next.js                                                                                                    |
| Package manager  | pnpm                                                                                                       |
| Install command  | `pnpm install --frozen-lockfile` (run from the repository root, so the whole workspace resolves correctly) |
| Build command    | `pnpm build` (equivalently `next build`, run with `apps/web` as the working directory)                     |
| Output directory | Managed by Next.js / Vercel's Next.js runtime — do not override                                            |
| Node.js version  | 22.x, matching the rest of the monorepo                                                                    |

Vercel natively understands pnpm workspaces when "Root Directory" is set to `apps/web`: it
installs from the repository root (so workspace dependencies resolve) and builds/serves only the
`apps/web` app.

## Production domain

- Target: `recall.sabahattinkalkan.com`
- Expected DNS record: a `CNAME` (or Vercel-managed `A`/`ALIAS`, depending on whether the domain's
  apex or a subdomain is used) pointing `recall.sabahattinkalkan.com` at the value Vercel provides
  once the domain is added to the project. The exact record is generated by Vercel at
  domain-attachment time and is not fabricated here.
- No DNS record exists or has been created for this yet.

## Environment variables

None are required for the initial release. `apps/web` has no server-side secrets and does not
call any external API. If a future capability genuinely requires one (e.g. a self-hosted search
provider), add it to `apps/web/.env.example` with a comment explaining why, and document it here
before deployment.

## What is explicitly not done by this document

- No Vercel project has been created.
- No domain has been attached.
- No DNS record has been created or modified.
- No deployment has been triggered.

## Manual steps to actually deploy (future, not run)

1. Create a Vercel project from the `sabahattink/Recall` GitHub repository.
2. Set "Root Directory" to `apps/web` in the Vercel project settings.
3. Confirm the framework preset is detected as Next.js.
4. Confirm the install command resolves the pnpm workspace (Vercel does this automatically for a
   detected pnpm monorepo; no override should be needed unless Vercel's defaults change).
5. Deploy once to a preview URL and verify `/`, `/docs`, `/examples`, `/changelog`, `/roadmap`,
   `/robots.txt`, and `/sitemap.xml` all resolve correctly.
6. Add the `recall.sabahattinkalkan.com` domain in the Vercel project's Domains settings.
7. Create the DNS record Vercel specifies at that point, in whatever DNS provider hosts
   `sabahattinkalkan.com`.
8. Promote the deployment to production once DNS has propagated and the domain shows as verified
   in Vercel.
